Link Mauve (Sep 25 2026 at 14:11):

Note that this driver and architecture aren’t the only ones having issues with 64-bit division, 32-bit PowerPC is also affected.

In c93c194e4ee71a734986fd99a8b1ec9fbb7a9b8b I had to make the __udivdi3 and __umoddi3 symbols panic at runtime in order to be able to build core, due to formatting of [iu]64, [iu]128 and core::time:Duration all making use of 64-bit division. The drm_panic_qr.rs driver also uses 64-bit division when compiled with CONFIG_CC_OPTIMIZE_FOR_SIZE=y.

Back then, I remember the discussions pointing to the idea to use different algorithms in the core crate, but nobody did step forward to implement that. The reasoning was that 64-bit division emulation is way too costly on 32-bit to be hidden behind a seemingly efficient / operator.
