When a userspace application calls the DRM_IOCTL_TYR_DEV_QUERY ioctl with a
mismatched buffer size, dev_query() breaks UAPI compatibility by performing
a strict-size copy that fails to truncate or zero-pad.

During ioctl handling, the Rust driver constructs a UserSlice bounded by the
userspace-provided devquery.size and immediately copies tdev.gpu_info into
it via writer.write(). Unlike standard DRM UAPI compatibility helpers (e.g.,
the C driver's PANTHOR_UOBJ_SET), which dynamically truncate reads for
undersized structs and zero-pad trailing bytes for oversized structs,
writer.write() lacks flexible boundary handling.

If a legacy userspace application provides an undersized buffer relative to
the kernel structure, writer.write() fails outright with -EFAULT instead of
completing a partial copy. Conversely, if userspace provides an oversized
buffer, trailing bytes beyond the kernel's structure size are ignored rather
than zeroed out. This rigid size enforcement guarantees ABI breakage, causing
older applications to fail and newer applications to consume uninitialized
memory in trailing buffer bytes.
