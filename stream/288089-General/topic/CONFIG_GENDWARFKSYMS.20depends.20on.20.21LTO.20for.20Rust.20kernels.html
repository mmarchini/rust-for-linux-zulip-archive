Topic: CONFIG_GENDWARFKSYMS depends on !LTO for Rust kernels

Adam Harshbarger (Sep 06 2026 at 17:12):

Working on a Linux lib/ → Rust port, we hit: CONFIG_GENDWARFKSYMS depends on !LTO ("Requires ELF object files"), and since CONFIG_RUST depends on !MODVERSIONS || GENDWARFKSYMS, a Rust kernel with module versioning currently can't use LTO at all.

A fat LTO object (-ffat-lto-objects) is already a real ELF object carrying both DWARF and bitcode, so the dependency looked relaxable to !LTO || CC_HAS_FAT_LTO_OBJECTS. Measured, not just proposed:

  • Builds with RUST=y LTO_CLANG_THIN=y MODVERSIONS=y GENDWARFKSYMS=y, boots, 636 self-tests, 0 failed.
  • All 13,774 exported-symbol fingerprints identical to a CONFIG_LTO_NONE=y control build.
  • Confirmed ld.lld genuinely consumes the embedded bitcode (a two-file test constant-folds across the compilation-unit boundary under the fat-object build, doesn't under a plain one) — not just tolerating the fat object format.

Doesn't put Rust itself in the LTO graph (.rs stays outside it, the separate unmerged Kangrejos 2023 problem) — this only unblocks LTO for the C side. Fat objects cost build time/size, and we saw 0.35% kernel text growth we haven't dug into.

Have this as a complete patch + repro script. Before sending formally: is this a real gap, or is there a known reason it hasn't been wired up already?
