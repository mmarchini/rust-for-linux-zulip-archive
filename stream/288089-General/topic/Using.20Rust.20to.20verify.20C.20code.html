Topic: Using Rust to verify C code

Natasha Klaus (Aug 24 2026 at 11:04):

We've built an approach for verifying the part of the Linux kernel written in C.

  1. Rewrite the C code in safe Rust.
  2. Use differential fuzzing to establish two things: that the new Rust behaves like the original C (conformance), and that the memory-safety bug class is gone, on the same input where the C does an out-of-bounds write, the Rust fails safely instead.
  3. Verify the Rust with our pipeline, described here: https://runtimeverification.com/blog/from-rust-source-code-to-mathematical-proof

We tried it on the UVC descriptor parser. Along the way the differential fuzzing surfaced a compiler-dependent signed-overflow UB in the original C, and we sent patches upstream: https://lore.kernel.org/linux-media/20260820111556.232652-1-natalie.klaus@runtimeverification.com/

Tested end to end on a UVC gadget over dummy_hcd, not on a physical camera.

Details of the work: https://runtimeverification.com/blog/hardening-linux-c-code-a-rewrite-and-verify-loop

What do you think? And if there's kernel code you'd like formally verified, or a property you'd want proved about it, we'd be glad to hear from you (DM me!)
