Topic: Ftrace and Livepatch Support For Rust

Matt Smith (Oct 13 2026 at 21:43):

Hi all!

I'm Matt and I work at Meta. We livepatch our fleet kernels without reboots, and as more kernel code becomes Rust (IMO a fantastic trajectory :) ), we're losing patchable surface. I want to make Rust functions live-patchable on through the same ftrace mechanism C uses, starting with the missing rustc compiler piece.

ARM live-patching support for Rust is in-scope for us since an increasingly sizeable amount of our fleet is ARM these days. My understanding is this would only require kernel-side changes since patchable entries are already emitted in LLVM and there's already an unstable rustc flag for it

On the x86 side I came across @Alice Ryhl 's Oct 2024 thread (lore link https://lore.kernel.org/all/20241008-cfi-patchable-all-v1-1-512481fd731d@google.com/): x86 ftrace needs __fentry__ hooks, which rustc cannot emit. -Z instrument-mcount gives legacy mcount, not fentry, and Peter confirmed Rust functions are untraceable on x86_64. The conclusion was that ftrace-for-Rust needs its own justification plus test evidence.

I'm signing up to produce the kernel-side half of this as well as pushing the necessary changes through rustc. My assumption is that since live-patching Kernel C code depends on ftrace support in C it would make sense to bring ftrace parity to Rust in order to for it to also support live-patching Kernel Rust code and thus provide enough justification for the kernel changes.

What I'd like to suss out:

1. Is anyone already working on fentry emission in rustc? I found no tracking issue but I don't want to duplicate effort if it can be avoided.
2. Is a -Z instrument-fentry-style flag setting LLVM's fentry-call attribute — sane? Plus a per-function opt-out (a no_instrument_function equivalent) for noinstr parity.
3. Reviewers/sponsors for the rustc PR once there is one.

Happy to file the rust-lang issue first if there's consensus on direction. This is my first time using this platform, so if there's a better place for this conversation, please let me know!
